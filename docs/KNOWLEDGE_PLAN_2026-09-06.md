## 2. How to read the plan

**Priorities.** P1 = blocks a correct decision the agent is asked to make today. P2 = needed to reach senior-staff level. P3 = depth or nice-to-have. Totals across the 54 agents: **P1 234 · P2 281 · P3 148** (department tables in §4; the per-agent P1 counts in supply, marketplace, finance, legal and exec each include one row for the shared delivery defect, so 26 of the 234 P1 rows close with the plumbing fix and no ingest — growth, customer_experience, product_eng, data_intel and people_ops record the same defect once as a finding instead of per agent).

**Ingest routes** (the audits name a route for every item):

- `agent_knowledge` profession row — the agent's own authored paragraph(s); rendered in LAYER 2 once the admission guard is fixed; also the only corpus the running exam grades against. Mark `validated` or it never counts as validated experience.
- `ops_knowledge` record (dept_key or role_key; record_type reference / policy / decision_playbook / decision_rule / SOP / failure_mode; embedded) — reachable by cosine match (`fn_ops_knowledge_match`), by keyword (LAYER 2c, exact `dept_key` only today), and by `fn_apply_playbook` for the deterministic path. `deterministic = true` records enter LAYER 2f.
- `kb_chunks` category — the deep corpus (statutes, standards, vendor docs, textbooks). Must be in a category inside the department's `fn_dept_scope` and embedded to be found by meaning; otherwise keyword-only.
- `decision_policy` key / threshold record — the numeric threshold as a key plus one deterministic policy record that cites the key by name, so the number reaches the prompt and stays in step with the code.
- Playbook / rule with if-then arms and worked examples — `decision_playbook` or `decision_rule` rows with explicit arms and ZZ DEMO cases; bound by `fn_apply_playbook` (cosine ≥ 0.85 and ≥ 2 lexemes covering ≥ 30%).
- `employee_knowledge` curriculum binding — the 12-layer standard row saying which domain the agent must hold at which depth; declarative, it binds no content by itself.
- Also used: `dept_library` row (LAYER 2b), `os_runbooks`, `response_template`, `metric_definition` / `employee_kpi.measure_sql`, `category_licence_activity` rows.

**Sizes** are the audits' estimates (characters, pages or record counts). "verify" marks a regulation, standard, portal or figure the auditor named from professional knowledge and did not open in the session — it must be checked against the primary source before ingest. "shared" means the item is written once and serves several agents.

## 7. Appendix — method, limits, disagreements, sources

**Method.** All eleven audits were run on 6 Sep 2026 between 02:00 and 03:30 UTC, read-only against the one production project `htdblwldjkcgjvmqkbeh`, under the 8-second statement timeout, with no paid model call and nothing written. Per agent the audits read `org_agents`, `org_role`, `employee_authority`, `agent_knowledge`, `employee_knowledge` and the compliance view, `ops_knowledge` (by dept_key, role_key, module, record_type, embedding and validation status), `kb_chunks` by category with full-text term censuses, `dept_library`, `decision_policy`, `phase_b_business_rule`, `phase_b_sla_policy`, `governance_rule`, `knowledge_exam_questions` / `knowledge_exam_results`, `kb_usage_log`, `agent_runs`, `review_chain`, `artifact_review`, `founder_alerts` and the cron tables, plus the deployed bodies of `fn_agent_context` (2- and 3-arg), `fn_agent_context_capped`, `fn_agent_context_v3`, `fn_ops_knowledge_search`, `fn_ops_knowledge_match`, `fn_apply_playbook`, `fn_knowledge_exam_sit`, `fn_knowledge_gaps` and the edge functions `agent_brain`, `knowledge_exam`, `kb_embed`, `route_inquiry`, `quote_compare`, `license_extract`. The STABLE 2-arg `fn_agent_context(key, 22000)` was executed once per agent; the production `fn_agent_context_capped` path is VOLATILE (it writes a retrieval-log row), so it was probed only inside `DO` blocks ending in `raise exception` (company-wide, finance, legal, exec, people_ops, product_eng, data_intel) and not executed at all by supply, marketplace, growth and CX. Numbers marked *derived* were read from a function body rather than executed; *verify* marks a regulation, standard, portal or figure named from professional knowledge and not opened. Depth scale: expert = can set the standard and decide edge cases unaided; working = executes correctly against a written rule; aware = knows it exists and when to hand off.
