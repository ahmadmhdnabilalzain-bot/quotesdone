# V3 runtime role reconciliation

14 August 2026. Companion to `V3_RUNTIME_ROLE_CROSSWALK.csv`, which is generated by
`node scripts/kb/v3_crosswalk.mjs <extracted-root>` and holds one row per packaged role and
per unclaimed runtime agent.

## What was reconciled

| | packaged | runtime |
|---|---|---|
| departments | 24 | 25 |
| roles / agents | 96 | 94 (93 active, 1 inactive) |
| category specialists | 86 | 86 catalogue routes |

## The finding that shaped the mapping

The packaged department names and the runtime `dept_key`s are **two vocabularies for the same
24 departments**, and nothing in the codebase bridged them. A string comparison resolved only
eight; the other sixteen looked like missing departments and were not.

The mapping was decided by reading each runtime charter, not by name similarity. Three would
have been mapped wrongly by any similarity measure:

| packaged | runtime | why |
|---|---|---|
| `admin_operations` | `knowledge` | its charter is *process, quality, project coordination and document control* — administration, not knowledge |
| `knowledge_learning` | `knowledge_eng` | its charter is *the knowledge base, retrieval, embeddings, validation, decay and the auto-learning exam loop* |
| `marketplace_operations` | `procurement` | its charter is *run intake → match → quote → reveal at high match & quote quality* |

The remaining 21 map on their obvious counterpart (`executive_office`→`exec`,
`strategy_evolution`→`evolution`, `ai_model_ops`→`ai_dept`, `data_analytics`→`analytics`,
`sales_crm`→`sales`, `payments_revenue`→`payments`, `it_cybersecurity`→`it`,
`business_development`→`bizdev`, `communications`→`comms`, `document_intelligence`→
`doc_intelligence`, `hr_people`→`hr`, `legal_compliance`→`legal`, `qa_testing`→`qa`, and the
seven whose names already agree).

`intelligence` is a 25th runtime department the package does not model separately — market,
competitive, supplier and customer intelligence plus forecasting. It shares the
`data_analytics` professional corpus, so one packaged department covers two runtime
departments. It is recorded in `org_department_alias` with `is_second_home = true`.

**Neither side was renamed.** The bridge is a row, so the next delivery with different names
costs an insert instead of a migration.

## Role archetypes

Every packaged role is one of four archetypes: `director`, `operations-specialist`,
`analyst-controller`, `reviewer-auditor`. Runtime agents carry arbitrary keys (`cfo`,
`bookkeeper`, `spec_mep`, `taxonomy_manager`), so the archetype is derived:

- **director** — exactly one per runtime department: the department's own `lead_agent`, or
  failing that its most senior agent. An earlier rule that called every `*_mgr` a director gave
  `bizdev` three directors and no specialist, which is not what that department does.
- **reviewer-auditor** — validation, verification, QA, moderation, fraud, risk, compliance,
  security, audit, trust.
- **analyst-controller** — analyst, analytics, BI, forecast, bookkeeping, financial, scoring,
  evaluation, coverage, intelligence, process improvement, optimisation.
- **operations-specialist** — everything else.

## Result

| mapping type | rows | distinct packaged roles |
|---|---|---|
| `one_to_one` | 41 | 41 |
| `package_composite` | 53 | 19 |
| `runtime_composite` | 36 | 36 |
| `on_demand_specialist` | 86 | 86 categories |

- **96 of 96** packaged roles resolved. None deferred, none inapplicable.
- **93 of 93** active agents hold at least one approved role identity. Zero run without one.
- `package_composite` — one packaged role identity shared by several runtime agents, because
  the department has more agents than the four archetypes (marketing has 7, procurement 8).
- `runtime_composite` — no agent in that department performs the archetype, so the department
  director carries it as a second identity. **No agent was created to fill a gap in a diagram.**
- The one inactive agent (`marketing_copy`) keeps its identity row and is `blocked`.

## Category specialists

The 86 packaged specialists are **on-demand identities, not standing agents**. Each is bound
to its existing `kb_operational_route` row in `org_category_identity`, and its knowledge is
retrieved at inquiry time by `fn_category_checklist`. The company does not run 182 agents.

- `org_department_alias` — 25 rows, packaged department → `dept_key`
- `org_role_identity` — 130 rows, agent → packaged role, archetype, mapping type, readiness
- `org_category_identity` — 86 rows, packaged category → catalogue route
