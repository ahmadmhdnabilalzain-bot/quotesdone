# Every attachment is read: inventory of upload paths (founder ruling 1177)

> "it should always read. there is no reason not to unless its extremely bad quality of attachment. the same applies to any attachment."

Branch `it_engineer/every-attachment-is-read`. Assigned: **sales_engineer** and **customer_support** (reading customer and supplier documents), **it_engineer** (the harness and the check).
Out of scope here: the supplier-side licence, company-profile and catalogue reading in `supplier_api` `process_docs`. PR #1285 handles those.

**The rule, in one place:** `supabase/functions/_shared/read_every_attachment.ts`.
1. **Code first.** `_shared/doc_read` `readDocument` runs first, with its security gate.
2. **Model second.** If the code reader finds no words, the file goes to the vision model through ai_gateway's existing `extract_text` route. No new route was added. If the answer comes back empty or too thin, the model is asked once more. On a provider failure, the gateway itself falls back to the route's second model (`attemptPlan`).
3. **Unreadable only when both attempts fail.** The caller then asks the uploader for a clearer copy with `clearerCopyAsk`. Suppliers are always asked in English. Customers are asked in their inquiry language.
4. **Refused is not unreadable.** A file the security gate refuses (executable, macro, polyglot, oversize) is marked refused.

"Before" is `origin/main` at 95758a4. "After" is this branch.
