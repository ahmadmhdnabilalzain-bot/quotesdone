# Postmortem: `duty:demo` — rehearsal windows and demo rows outlived their run

Seat: it_engineer. Blameless. Written 28 Sep 2026 from production reads (read-only) and `git log`.

| | |
|---|---|
| Class | `duty:demo:*` — 41 distinct keys (`duty:demo:window:<id>` and `duty:demo:<table>`) |

| Answering seat | ceo |

## Impact
Internal. An open rehearsal window suppresses the failed-run watcher for whatever it covers, so while a window stays
open a real failure in that scope can go unpaged. Two `demo customers` and one `demo leads` row outlived their run by
six hours (18 Sep 21:01Z); ZZ DEMO rows are never shown to a real user.

## Root cause
A run (`scripts/e2e/run.mjs`, `demo_factory.withRun`, the checks under `scripts/checks/`) opened a `rehearsal_window` and
exited without closing it — a crash or timeout skipped its `finally`. Each key names one window, so the 41 are 41
separate abandoned runs, not one fault seen 41 times.

## Detection
`it_engineer.demo` duty. Handled deterministically: `fn_seat_answers_it_finding` closes the window as the CEO's remedy
(`scripts/sql/the_it_engineer_closes_every_loop_it_opens.sql`, section 5).

## Fix (found in git)
- `aa96d9c`: the answering routine closes a rehearsal window a run left open.
- `ce156db` / `cec2d4c` (#683): a rehearsal never queues a backup.
- Runs still abandon windows; **the leak itself is not fixed**, only its consequence is repaired each time.

## Action items
1. **it_engineer** — close the window in the process-exit path of `demo_factory.withRun` and `scripts/e2e/run.mjs`, not only in `finally`.
2. **it_engineer** — this class is self-healing and should not open `it.finding` handoffs at high severity; route it as a deterministic repair.
