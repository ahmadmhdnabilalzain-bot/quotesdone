# QuotesDone — Global Chain-of-Command Rules

## Primary hierarchy

Founder → AI CEO → department heads → operators/specialists → internal reviewers where required.

## Founder-command entry

Founder → Chief of Staff → canonical command intent/workflow → exact accountable owner → child tasks/contributors/reviewer → result → Chief of Staff founder thread.

- Clear command: command plan and initial tasks are created atomically.
- Ambiguous command: one clarification question; no operational task is created.
- Chief of Staff coordinates and reports; it does not take ownership away from the workflow owner.
- Founder commands do not create a second founder approval request.

## Autonomous-company entry

Customer/supplier/schedule/KPI/system/workflow event → canonical event router → frozen Phase B workflow and step → exact accountable role → contributor/specialist/overlay → independent review → outcome/KPI/manager response.

- Routine autonomous work bypasses the founder and Chief of Staff.
- Chief of Staff participates only for founder commands, ambiguous ownership, material cross-department coordination, stalled executive work, and founder-facing summaries.
- AI CEO participates only in company objectives, cross-department reprioritization, material company-performance gaps and executive conflicts.

## Approval rule

The only routine founder approval is a specific refund approve/reject decision. All other normal reviews are internal AI employee decisions. Founder-reserved policy changes occur only when the founder initiates a command; that command is already the authorization source.

## Task ownership

Every task has exactly one canonical accountable role. Technical identities such as `service_role`, `system`, `operations_ai`, `Director`, or a function name may be system actors but never the business owner.

## Reviewer independence

A creator and final consequential reviewer must resolve to different effective canonical identities. Aliases do not create independence.
