# Construction Materials Suppliers

**Overlay ID:** `opcat-001`  
**Catalog number:** 1  
**Canonical slug:** `construction-materials-suppliers`  
**Status:** `ON_DEMAND_OVERLAY`

## Operational reporting path

`marketplace_director` — Marketplace Director → `rfq_qualification_manager` — RFQ Qualification Manager → `inquiry_router` — Inquiry Router → `opcat-001` → result returns to `rfq_qualification_manager` — RFQ Qualification Manager

## Knowledge-governance path

`category_knowledge_curator` — Category Knowledge Curator → `taxonomy_governance_manager` — Taxonomy Governance Manager → `knowledge_validator` — Knowledge Validator

## Broad-domain escalation

`construction_civil_domain_specialist` — Construction & Civil Domain Specialist

## What the overlay owns
- Provide category and subcategory terminology.
- Provide minimum-sufficient inquiry questions and mandatory/optional fields.
- Apply never-infer rules and identify unsupported assumptions.
- Identify pricing drivers, required documents, technical comparison fields, regulatory triggers and quote-readiness blockers.
- Return bounded specialist advice to the RFQ Qualification Manager.

## What the overlay cannot decide
- Own a standing task or department.
- Dispatch suppliers.
- Approve suppliers.
- Reveal customer identity.
- Move money or approve refunds.
- Change founder policy.
- Issue final legal/privacy/regulatory verdicts.
- Close the parent workflow independently.

## Founder manual-command behavior

Founder → Chief of Staff → relevant canonical workflow/owner → Inquiry Router or supplier-coverage workflow → overlay invocation. The overlay is never the command-plan owner.

## Normal autonomous behavior

Customer inquiry or supplier-network event → canonical Phase B workflow → Inquiry Router/RFQ Qualification Manager → overlay → result returns to RFQ Qualification Manager.

## Trace requirement

`TRACE-CATEGORY-ADVICE` is mandatory for every invocation.

**Overlay ID:** `opcat-082`  
**Catalog number:** 82  
**Canonical slug:** `gas-systems-suppliers`  
**Status:** `ON_DEMAND_OVERLAY`

## Operational reporting path

`marketplace_director` — Marketplace Director → `rfq_qualification_manager` — RFQ Qualification Manager → `inquiry_router` — Inquiry Router → `opcat-082` → result returns to `rfq_qualification_manager` — RFQ Qualification Manager

## Knowledge-governance path

`category_knowledge_curator` — Category Knowledge Curator → `taxonomy_governance_manager` — Taxonomy Governance Manager → `knowledge_validator` — Knowledge Validator

## Broad-domain escalation

`mep_domain_specialist` — MEP Domain Specialist

## What the overlay owns
- Provide category and subcategory terminology.
- Provide minimum-sufficient inquiry questions and mandatory/optional fields.
- Apply never-infer rules and identify unsupported assumptions.
- Identify pricing drivers, required documents, technical comparison fields, regulatory triggers and quote-readiness blockers.
- Return bounded specialist advice to the RFQ Qualification Manager.

## What the overlay cannot decide
- Own a standing task or department.
- Dispatch suppliers.
- Approve suppliers.
- Reveal customer identity.
- Move money or approve refunds.
- Change founder policy.
- Issue final legal/privacy/regulatory verdicts.
- Close the parent workflow independently.

## Founder manual-command behavior

Founder → Chief of Staff → relevant canonical workflow/owner → Inquiry Router or supplier-coverage workflow → overlay invocation. The overlay is never the command-plan owner.

## Normal autonomous behavior

Customer inquiry or supplier-network event → canonical Phase B workflow → Inquiry Router/RFQ Qualification Manager → overlay → result returns to RFQ Qualification Manager.

## Trace requirement

`TRACE-CATEGORY-ADVICE` is mandatory for every invocation.
