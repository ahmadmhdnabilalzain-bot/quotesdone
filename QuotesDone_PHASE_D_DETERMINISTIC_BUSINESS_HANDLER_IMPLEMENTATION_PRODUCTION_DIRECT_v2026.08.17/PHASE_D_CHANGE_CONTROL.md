# Change Control

Phase D implements frozen design.

A role/department/manager change requires Phase A change request.
A workflow/step/owner/state/gate/rule/handoff/founder-boundary change requires Phase B change request.
A kernel contract change requires Phase C change request.

Required: defect evidence, affected frozen item, current/proposed behavior, owner/reviewer/state/gate impact, security/privacy/finance impact, compatibility, migration/rollback and founder approval need.

Repair implementation to the frozen design instead of changing the design to match broken code.
