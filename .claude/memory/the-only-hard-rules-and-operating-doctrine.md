LLM / OpenRouter DOCTRINE (supersedes the looser "90% no-LLM"):
- **Internal company operation ≈ 95% deterministic CODE + linked knowledge, ~5% LLM** (founder corrected
  "not zero"). All agent DECISIONS, reasoning, inter-department communication, approvals, evaluation, and
  improvement are deterministic. The ~5% internal LLM is ONLY for the genuinely-external or generative work:
  (a) **marketing/analytics agents reading ONLINE data** — Meta/campaign insights + metrics, comparing
  performance, deciding what to change; (b) **content creators GENERATING content** — social posts,
  animated videos, images (to be wired to OpenArt AI, maybe OpenAI, once the code is done).
- **OpenRouter/model is otherwise a thin EXTERNAL-EDGE adapter only**: confirming a law/reg actually changed
  online, and talking to external platforms (Meta, Stripe) to check/confirm state.
- **Chat surfaces** (website home, customer portal, supplier portal) may use the model, minimally.
- Founder expects this means ~**200 new deterministic functions** encoding the reasoning that today wrongly
  routes to the model, and hours of redesign. Today it's inverted (every workflow's ENTRY step calls the
  model, deterministic logic is only a fallback) — the redesign makes deterministic code the DEFAULT and
  only internal path. See [[reasoning-layer-semantic-retrieval]], [[against-production-gates-vs-a-running-company]].

OPERATING MODEL (the spine): program the agents EXACTLY like a real company on the org chart. **Every agent
is ACTIONABLE** — none is a mere reader/notifier; each takes actions, receives reactions from other
departments, routes work onward, is evaluated by its manager/evaluator, and improves. **Everyone is
connected and in the loop** — no dead-end / single connection. Approvals flow up the hierarchy (agent →
line manager → dept head → exec/board), refunds → founder. The loop must TURN end-to-end deterministically.
This is exactly what the audit found BROKEN ([[master-audit-verdict-and-redesign]]): the loop is dead
(no workflow completes since 14 Aug), agents park at the model step, many are reader/notifier, 12 workflows
have trigger events never emitted, org_tasks duplicates the workflow spine. The redesign must fix all of it.

THE GOAL LADDER (ingested at the top): as the FINAL step after the structure is in place, seed the CEO agent
with the first-year business plan — the **revenue target (AED 1M)**, **# suppliers to register**,
**# customers to register**, and the **month-by-month financial forecast** to reach it. The CEO then
CASCADES it: CEO → department objectives → each agent's tasks, and chases delivery. Every department/agent's
work must tie back to this north star. Half-built today: company_goals has the AED 1M line but only exec+
finance link to it and 29/92 department_objective rows have null goal_key — build the full cascade.
