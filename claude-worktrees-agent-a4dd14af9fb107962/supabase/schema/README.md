# Supabase schema mirror

`full_schema.sql` is a complete definition export of the live database
(project `htdblwldjkcgjvmqkbeh`, "suppliers DB"), generated by introspecting
the running Postgres instance. It is the "GitHub has whatever is in Supabase"
mirror for the database layer. Edge-function source lives separately under
`supabase/functions/`.

## What it contains

- Extensions, sequences
- All **216 tables** (reconstructed `CREATE TABLE`)
- All constraints (PK / FK / unique / check) and non-constraint indexes
- All **66 views**
- All **324 user-defined functions** (extension-owned functions are excluded)
- All **71 triggers**
- Row-Level-Security enable statements for the **214 RLS-protected tables**, plus the 3 policies
- All **114 pg_cron jobs** (`cron.schedule(...)` calls)
- The **names** of every `app_secrets` key, as comments

## What it deliberately excludes

- **Secret values.** `app_secrets` holds live credentials (Stripe key, tokens,
  webhook secrets). Only the key *names* are mirrored, as comments. Values are
  never written to git.
- **Row data.** No table contents — customer/supplier PII and business data stay
  in Supabase only (also the correct call under PDPL).

## Fidelity

This is a faithful **reference** mirror, not a guaranteed one-click restore:
statement ordering is best-effort and table DDL is reconstructed from catalogs.
For a byte-perfect, restorable backup use Supabase's managed backups / PITR, or
`pg_dump` with database credentials. Supabase remains the source of truth; this
file is the human- and git-readable copy of the system definition.

## Refreshing

Generated on 2026-07-24 during the CTO-audit hardening work. It can be
regenerated any time by re-running the introspection export, and can be
automated to refresh nightly alongside the existing `github_org_sync` job.
